КОПИЛКА ПРИЗОВ — ВЕРСИЯ 21
Облачная синхронизация Firebase + изолированный тестовый режим папы

СОСТАВ АРХИВА
- index.html — приложение и подключение Firebase.
- sw.js — Service Worker с новым кэшем v21.
- manifest.json, иконки — PWA-файлы.
- firestore.rules — правила безопасности Firestore (их нужно отдельно опубликовать в Firebase Console).

ВАЖНО: ОБЛАКО НЕ ЗАРАБОТАЕТ, ПОКА НЕ ВКЛЮЧЕНЫ СЕРВИСЫ FIREBASE И НЕ ОПУБЛИКОВАНЫ ПРАВИЛА
Параметры проекта kopilka-bc12a уже внесены в index.html. Firebase API key — публичный идентификатор веб-приложения; безопасность обеспечивается Firebase Authentication и правилами Firestore, а не сокрытием этого ключа.

ПЕРВОНАЧАЛЬНАЯ НАСТРОЙКА FIREBASE (ОДИН РАЗ)
1. Открой https://console.firebase.google.com/ и выбери проект kopilka-bc12a.
2. В разделе Build → Authentication → Sign-in method включи Email/Password.
3. В разделе Build → Firestore Database создай базу данных (если она ещё не создана). Выбери регион, близкий к пользователям; после создания регион изменить нельзя.
4. Открой Firestore Database → Rules. Скопируй всё содержимое файла firestore.rules из архива в редактор правил и нажми Publish.
5. В разделе Project settings → Your apps проверь, что веб-приложение соответствует параметрам Firebase, уже внесённым в index.html.
6. Не включай публичные тестовые правила вида allow read, write: if true.

ПЕРВЫЙ ЗАПУСК И ПЕРЕНОС СУЩЕСТВУЮЩИХ ДАННЫХ
1. Сначала на телефоне, где сейчас находятся правильные накопления и история сына, открой текущую версию приложения v20 и скачай резервную копию в разделе «Данные».
2. Установи v21, войди в неё и зарегистрируй отдельный семейный аккаунт папы (email + пароль).
3. Нажми «Создать семейное облако». Приложение создаст уникальный код семьи и перенесёт текущие локальные данные этого телефона в production.
4. Сохрани код семьи. Не публикуй его и не отправляй посторонним.
5. На телефоне папы открой v21 и войди под тем же email/паролем, который использовался при создании семейного облака. Данные подтянутся автоматически.
6. На телефоне сына выйди из аккаунта папы кнопкой «Выйти», зарегистрируй отдельный email/пароль сына и введи код семьи. Этот аккаунт получает роль «Сын».
7. После подключения проверь совпадение билетов, денежного баланса, призов, истории и заявок на обоих телефонах.

РЕКОМЕНДУЕМАЯ ПОСЛЕДОВАТЕЛЬНОСТЬ УСТРОЙСТВ
- Устройство с исходными данными: аккаунт папы → «Создать семейное облако» (перенос локальных данных).
- Телефон папы: тот же аккаунт папы → код семьи уже сохранён, данные подтянутся автоматически.
- Телефон сына: отдельный аккаунт сына → «Подключить этот телефон к семье» → ввести код семьи.

РАБОЧИЙ И ТЕСТОВЫЙ РЕЖИМ ПАПЫ
- «Рабочий» использует families/{familyId}/spaces/production/state/main.
- «Тестовый» использует families/{familyId}/spaces/test/state/main.
- При первом входе в тестовый режим создаётся отдельная копия рабочего состояния на момент включения теста.
- Последующие изменения тестовой копии не записываются в production.
- Правила Firestore запрещают аккаунту сына читать или изменять test; запись в production разрешена папе и сыну.
- Сброс тестового режима можно выполнить удалением документа families/{familyId}/spaces/test/state/main в консоли Firestore; при следующем входе папы он будет создан заново из текущего production.

СИНХРОНИЗАЦИЯ И ОГРАНИЧЕНИЯ
- Данные приложения синхронизируются одним документом состояния; локальная копия localStorage остаётся на каждом устройстве.
- Для защиты от незаметной перезаписи добавлен номер ревизии и транзакционная проверка. Если два телефона изменили данные почти одновременно, устаревшее сохранение не перезапишет новую облачную версию: приложение загрузит последнюю версию и попросит повторить последнее действие.
- Не выполняйте одновременно одно и то же подтверждение/начисление на двух телефонах.
- Синхронизация требует интернет-соединения. При отсутствии сети изменения могут оставаться только локально до следующего успешного сохранения; перед важными действиями дождитесь сообщения «Синхронизировано с облаком».
- Это клиентская PWA. В этой версии проверка целостности бизнес-операций не вынесена в Cloud Functions: правила ограничивают доступ к рабочему и тестовому пространству, но не заменяют серверную валидацию каждого начисления. Не используйте тестовый режим для реальных начислений.
- Email/пароль Firebase — отдельная учётная запись, не пароль папы из старой локальной версии.

ОБНОВЛЕНИЕ GITHUB PAGES

2. Замени файлы приложения в корне GitHub-репозитория. Добавь firestore.rules в репозиторий для хранения копии правил (публикация правил всё равно выполняется в Firebase Console).
3. Выполни Commit changes и дождись публикации GitHub Pages.
4. Открой приложение на телефоне и нажми «Обновить».
5. Не удаляй данные сайта и не очищай хранилище браузера до проверки переноса.
